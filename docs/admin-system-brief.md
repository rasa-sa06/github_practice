## デモが定義している画面

タブは4つ。スマホ幅で設計されています。

### ① きょう（今日やることダッシュボード）

開くと「おかえりなさい」「きょうやることは3つです。上から順にどうぞ。」から始まります。

- **まずはこれから** — 大きく1件だけ。例：「ゆきさんに返信する」＋届いた相談の要約＋「返信をひらく」ボタン
- **そのあとで** — 小さく薄く2件。制作中のもの（8個のうち5個できています）、発送待ちのもの
- **きょうのクエスト** — 「アプリをひらく」「返信をひとつ返す」「リボンを1つ仕上げる」。
  普段の仕事を進めるだけで埋まる

### ② 注文（ステータス管理）

進行中が上、終わったものは下。1行に お客様名／内容／ステータス／補足。

6段階：**お問い合わせ → 打ち合わせ → 制作中 → 完成 → 発送 → お届け完了**

色は3色だけ。**ピンク＝相手の番／琥珀＝自分の作業中／緑＝完了**

注文を開くと（注文の中身）:

- **いまここ** — 6段階のどこにいるか。日付つき
- **1個できた** ボタン — 押すだけで進む。数の入力も日付選択もしない
- **お聞きしていること** — 納期・色・数量などを上に固定表示。過去のやりとりを遡らなくて済む
- **LINEをひらく** — やりとりはLINEのまま。画面から直接開く

### ③ 文章をつくる（AI文章サポート）

写真から、載せる文章の下書きを作ります。

- **どこに載せますか** — minne ／ Instagram ／ ホームページ。載せ先で長さと語り口を変える
- **下書き** — 生成された文章。「別の書き方にする」「これを使う」
- 過去の投稿やホームページの文章から、いつもの言い回しを拾う
- 置き換えるためではなく、**一から考える必要をなくす**のが目的

### ④ きろく（続けたくなる仕掛け）

- 数字4つ：今月つくったリボン／今月お届けした注文／これまでの注文／続いている日数
- **あつめたもの**（バッジ）：はじめての団体オーダー、10個つくった、1週間つづいた、50個つくった、季節をひとまわり
- **今週**：「5個仕上げて、2件お届けしました。」

## 設計ルール（実装で外してはいけないもの）

デモはこのルールに沿って作られています。**機能ではなく制約として扱ってください。**

| ルール | 具体的に |
|---|---|
| **一手だけ** | 大きく出るのは常に1つ。残りは意図的に小さく薄く。迷う時間を作らない |
| **責めない** | 「未対応◯件」「◯日経過」を表示しない。**赤も警告色も使わない** |
| **再開できる** | 何日ぶりでも「おかえりなさい」から始まる。空白を指摘しない |
| **入力は一度** | 聞いた内容は1回書けば、以降どの画面からも見られる |
| **押すだけで進む** | 数値入力や日付選択をさせない。「1個できた」ボタン |
| **色は3色** | ピンク＝相手の番／琥珀＝自分の作業中／緑＝完了。それ以上増やさない |
| **数えるのはやったことだけ** | 「残り◯個」ではなく「◯個つくった」。止まっていた期間を途切れとして見せない |
| **作業を増やさない** | ゲーム要素のための操作を追加しない。普段の仕事がそのまま反映される |
| **スマホだけで完結** | PCを前提にしない |

> 提案書の冒頭には、これらのルールの理由にあたる依頼者本人の事情が書かれています。
> このリポジトリは公開されているため転記していません。
> **実装に入る前に、必ず提案書の原本を読んでください。**

## 技術的に必要なもの

現在のサイトは静的HTMLで、JavaScriptを1行も使っていません。
管理システムはこの延長では作れず、最低限これが要ります。

- **データを保存する場所**（注文・お客様・進捗・実績）
- **ログイン**（本人だけが開ける状態にする）
- **LINE Messaging API**（相談の受信。今の友だち追加リンクとは別物）
- **AIによる文章生成**（③のため）

### 判断が必要な点

> この3点への回答は [`tech-stack-proposal.md`](tech-stack-proposal.md) にまとめています。
> **まだ案の段階で、決定ではありません。**

- **同じリポジトリに入れるか、分けるか**
  今のリポジトリは静的サイト用です。管理システムを同居させるか、別リポジトリにするか。
- **ホスティング**
  サイトはVercelで動いています。管理システムも同じにするか。
- **どこまで自作するか**
  ステータス管理だけならスプレッドシート＋簡易画面でも成立します。
  注文が月に数件なら、作り込みが負債になる可能性があります。

## 着手前に依頼者と決めること

1. **注文は月にどのくらいありますか**
   規模によって作るものが変わります。月数件なら、管理画面よりLINEのやり取りの方が速いという
   結論も十分あり得ます。**ここを確認せずに作り始めないでください。**
2. **今どこで一番困っていますか**
   ダッシュボードから作るか、ステータス管理から作るか、優先順位が決まります。
3. **どこから使い始めたいですか**
   4画面すべてを一度に作る必要はありません。1画面だけ動くものを先に渡す方が、
   使われるかどうかが早く分かります。
